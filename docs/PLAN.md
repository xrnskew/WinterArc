решения. ТЗ — в [BRIEF.md](BRIEF.md). Этот файл обновляется после каждого этапа.

## 1. Структура папок

Главное правило: `domain/` — чистая логика на TypeScript без React, её можно
читать и тестировать отдельно. Экраны только показывают данные и вызывают действия.

## 2. Модель данных

Принцип: храним только факты, всё остальное вычисляем. Серии, индекс, прогнозы
и итоги считаются в `domain/`, поэтому рассинхрона не будет.

```ts
// ── Базовые типы ─────────────────────────────────────────
type Id = string;        // crypto.randomUUID()
type DateKey = string;   // "2026-10-01" — локальная дата без времени
type Timestamp = string; // "2026-10-01T21:15:00.000Z" — момент времени
type Weekday = 1 | 2 | 3 | 4 | 5 | 6 | 7; // 1 = понедельник

// ── Корень: ровно это лежит в localStorage ───────────────
interface AppData {
  version: number;                 // версия схемы → миграции
  settings: Settings;
  activeArcId: Id | null;          // null → показываем онбординг
  arcs: Arc[];
  habits: Habit[];
  habitLogs: HabitLogs;
  ratingScales: RatingScale[];
  days: Record<DateKey, DayEntry>; // оценки и заметка дня
  goals: Goal[];
  tasks: Task[];
  weeklyReviews: Record<DateKey, WeeklyReview>; // ключ = понедельник недели
  achievements: UnlockedAchievement[];
  dashboard: WidgetInstance[];     // порядок массива = порядок на экране
}

// ── Арка ─────────────────────────────────────────────────
interface Arc {
  id: Id;
  name: string;         // "Winter Arc 2026"
  why: string;          // зачем я это делаю
  startDate: DateKey;   // по умолчанию 1 окт
  endDate: DateKey;     // по умолчанию 31 дек
  habitIds: Id[];       // привычки этой арки, в порядке показа
  createdAt: Timestamp;
  archivedAt: Timestamp | null;
}

// ── Привычки ─────────────────────────────────────────────
type Schedule =
  | { type: 'daily' }
  | { type: 'weekdays'; days: Weekday[] }
  | { type: 'timesPerWeek'; times: number };

type AccentKey = 'snow' | 'frost' | 'silver' | 'steel' | 'ash' | 'smoke';

interface HabitBase {
  id: Id;
  name: string;
  icon: IconName;      // ключ из набора ~40 иконок
  accent: AccentKey;   // ключ, а не цвет: тема решает, как он выглядит
  schedule: Schedule;
  createdAt: Timestamp;
  archivedAt: Timestamp | null;
}
interface CheckHabit extends HabitBase { kind: 'check' }
interface CountHabit extends HabitBase { kind: 'count'; unit: string; dailyTarget: number }
interface TimeHabit extends HabitBase { kind: 'time'; targetMinutes: number; targetPeriod: 'day' | 'week' }
type Habit = CheckHabit | CountHabit | TimeHabit;

// habitLogs[habitId][date] = значение за день. Нет записи — значит 0.
// check → 1, count → штуки, time → минуты.
type HabitLogs = Record<Id, Record<DateKey, number>>;

// ── Оценки дня ───────────────────────────────────────────
interface RatingScale { id: Id; name: string; icon: IconName; archivedAt: Timestamp | null }
interface DayEntry {
  ratings: Record<Id, number>;   // ratings[scaleId] = 1..10
  note: string;
}

// ── Цели и задачи ────────────────────────────────────────
interface GoalBase {
  id: Id;
  title: string;
  deadline: DateKey | null;
  arcId: Id | null;              // цель может жить и вне арки
  createdAt: Timestamp;
  completedAt: Timestamp | null;
  archivedAt: Timestamp | null;
}
interface StepsGoal extends GoalBase {
  kind: 'steps';
  steps: { id: Id; title: string; doneAt: Timestamp | null }[];
}
interface NumericGoal extends GoalBase {
  kind: 'numeric';
  unit: string;                  // "₽", "кг", "км"
  startValue: number;
  targetValue: number;           // может быть меньше старта (вес вниз)
  entryMode: 'add' | 'set';      // add — пополнения (₽, км), set — замеры (вес)
  entries: { id: Id; date: DateKey; value: number; note: string }[];
}
type Goal = StepsGoal | NumericGoal;

interface Task {
  id: Id;
  title: string;
  goalId: Id | null;
  priority: 'low' | 'medium' | 'high';
  deadline: DateKey | null;
  doneAt: Timestamp | null;
  createdAt: Timestamp;
}

// ── Обзор недели, достижения, виджеты, настройки ─────────
interface WeeklyReview { wins: string; misses: string; nextFocus: string; updatedAt: Timestamp }
interface UnlockedAchievement { id: string; unlockedAt: Timestamp } // id: "streak-30:<habitId>"

// Отсчёт и прогресс арки — не виджеты: они всегда сверху командного центра (v3).
type WidgetType =
  | 'discipline' | 'today' | 'week' | 'streak' | 'ratingTrend'
  | 'heatmap' | 'goal' | 'tasks' | 'why';

interface WidgetInstance {
  id: Id;
  type: WidgetType;
  size: 'half' | 'full';
  habitId?: Id; goalId?: Id; scaleId?: Id; // настройка конкретного виджета
}

interface Settings {
  themeId: 'winter';
  snow: 'off' | 'light' | 'snow' | 'blizzard'; // выкл / лёгкий снег / метель / буран
  performance: 'auto' | 'full' | 'lite';        // auto = определить по устройству
}
```

**Миграции.** В `migrations.ts` лежит объект `{ 2: (v1) => v2, 3: (v2) => v3 }`,
и `migrate()` проходит по шагам до `CURRENT_VERSION`. Перед миграцией сырые данные
копируются в отдельный ключ `winterarc:backup:v{N}`. Если данные новее приложения,
мы их не трогаем и показываем предупреждение. Импорт JSON проходит через тот же
`migrate()`, поэтому старый бэкап откроется в любой новой версии.

## 3. Дизайн-система

Все значения — в `src/design/themes/winter.ts`. `applyTheme()` пишет их
в CSS-переменные `--wa-*`, `global.css` связывает переменные с классами Tailwind
(`bg-night`, `text-muted`, `border-gray-700`…). Стандартные палитры Tailwind
отключены: в разметке доступны только цвета темы. Шейдер и графики берут те же
значения из TS. Новая тема — новый файл в `themes/`.

### Цвета

| Токен | Значение | Где |
| --- | --- | --- |
| night | #0a0a0a | фон, ночь |
| graphite | #1a1a1a | основа панелей |
| gray-800…300 | #2a2a2a #3a3a3a #4d4d4d #666 #808080 #9a9a9a | рамки, черты, графики |
| text | #e8e8e8 | основной текст |
| text-muted | #9a9a9a | подписи — самый тёмный допустимый для текста |
| number | #ffffff | цифры-табло |
| danger | #bc5050 | просроченные задачи и дедлайны: черты, рамки, иконки |
| danger-text | #d07a7a | просроченные задачи и дедлайны: текст |
| danger-soft | danger 15% | подложка |
| glass | rgba(16,16,16,.66) + blur(16px) + граница rgba(255,255,255,.08) | карточки |
| glass-lite | rgba(22,22,22,.94) без blur | карточки на слабых устройствах |

**Контраст (WCAG AA).** Текст пишем только цветами `text`, `text-muted`, `number`,
`danger-text`: они дают ≥ 4,5:1 даже в худшем случае, когда за стеклом проплывает
размытая снежинка. `#808080` и темнее — только рамки и графика (≥ 3:1 для черт
и иконок). Правило проверяет `themeContrast.test.ts`: тема, нарушающая его,
не пройдёт тесты. Исходный красный `#9e3b3b` давал 2,96:1 и не годился даже для
черт — поэтому красный разделён на `danger` и `danger-text`.

Акценты привычек (вместо цветов — 6 оттенков): снег #fff, иней #dcdcdc,
серебро #bdbdbd, сталь #9e9e9e, пепел #8a8a8a, дым #757575. В данных хранится
ключ, будущая цветная тема сможет дать им настоящие цвета. На графиках привычки
различаются оттенком и пунктиром.

### Шрифты

- **Oswald 500** — заголовки экранов, заглавными, разрядка 0.04em
  (Bebas Neue не поддерживает кириллицу)
- **Golos Text 400/500** — основной текст (сделан для русских интерфейсов)
- **JetBrains Mono** — только цифры, `tabular-nums`, чтобы не прыгали при пересчёте

Шкала размеров: 12 · 14 · 16 · 18 · 21 · 24 · 36 · 48 · 72 · 96 px.
Радиусы: 2 / 4 / 8 px. Анимации: 120 / 220 / 600 мс, пересчёт цифр 900 мс
(ease-out-expo).

### Принятые правила (по методичке плагина frontend-design)

1. Заглавные — только в крупных заголовках экранов. Подписи — обычным регистром,
   без разрядки.
2. Моноширинный шрифт — только для цифр, не для подписей.
3. Основной текст — Golos Text вместо Inter.
4. Не всё — карточки: отсчёт в командном центре стоит прямо на метели, стекло —
   только для групп (виджеты, чек-ин).
5. Фирменный элемент — «зарубки»: вся арка лентой, один день = одна черта.
6. Анимации: метель — фон; пересчёт цифр — только когда число изменилось
   от действия (и один раз при первом открытии за день); карточки не «выплывают»;
   вспышка при отметке — ответ на действие.
7. Тексты: кнопка говорит, что сделает («Сохранить»), уведомление повторяет то же
   слово («Сохранено»); пустой экран подсказывает следующий шаг; ошибки без
   извинений; без «→» на кнопках и строк вида «A · B · C».

### Зарубки (design/ui/tally)

- Прошедший день светлеет от `gray-600` до белого по индексу дисциплины,
  сегодня — выше остальных и со свечением, будущие — короткие риски
  `gray-700`.
- Дни сгруппированы по календарным неделям, между неделями — зазор.
- Если на одну строку место под день меньше 4px, лента переносится на 2–4 строки
  по целым неделям, и дни недели стоят столбцами (понедельники друг под другом).
- Телефон 360–390px: арка 92 дня → 2 строки по 7 недель, черта 3px, зазор 3px.
  В одну строку черта была бы 1,5px — проверено скриншотами, слишком мелко.
- Подпись «День N из M»: в одну строку — прямо под сегодняшней чертой,
  в несколько строк — слева под лентой.

### Метель

- 3 / 5 / 7 слоёв (лёгкий снег / метель / буран). Ближние хлопья крупные, чёткие,
  быстрые, их сильнее сносит; дальние — мелкие, размытые, медленные, тусклые.
- Ветер (`wind.ts`): ровный ветерок + порывы раз в 5–14 с (нарастание, пик,
  затихание). Шейдеру передаётся накопленный снос, поэтому смена скорости
  не даёт рывков. В порыв ближние хлопья смазываются вдоль полёта.
- Позёмка: вытянутый шум в нижних 15% экрана, непрозрачность 2,5–6,5%.
- Производительность: рендер в 0,6–0,75 от размера экрана, лимит 30 FPS,
  анимация по времени, пауза при скрытой вкладке.
- «Уменьшить движение» в системе → один застывший кадр (и у CSS-снега тоже).
- Слабое устройство (нет WebGL, ≤ 2 ядер, ≤ 2 ГБ памяти, экономия трафика) или
  меньше 20 FPS в первые 3 с (в режиме «Авто») → CSS-снежинки, стекло без размытия.
  Порог — 50 мс на кадр, а не 40: на экранах 75 Гц честные 30 FPS дают ровно 40 мс.

### Навигация

Телефон — нижний бар: Центр · Привычки · Чек-ин (крупная приподнятая кнопка) ·
Цели · Ещё. Во «Ещё» — аналитика, обзор недели, достижения, настройки.
Десктоп (от 768px) — узкая боковая панель со всеми экранами.

### Типы привычек, арки, индекс дисциплины

- Три типа привычек: да/нет, количество, время. Тип «Отказ» убран (раздел 6).
- Привычки живут между арками: при создании новой арки выбираешь, какие взять
  с собой. История привязана к датам.
- Индекс дисциплины 0–100: каждая привычка даёт за день оценку 0…1 (да/нет → 0
  или 1; количество и время → min(факт / цель, 1)).
  Индекс дня — среднее по привычкам, запланированным на этот день. Гибкие привычки
  («N раз в неделю», недельная цель по времени) идут только в индекс недели
  как min(сделано / цель, 1).

## 4. Решения этапа «б»

### Хранение

- Ключ данных — `winterarc:data`. Сохраняем после каждого изменения (данных мало,
  запись мгновенная). Перед миграцией сырые данные копируются в
  `winterarc:backup:v{N}`.
- Нечитаемые данные (битый JSON, нет разделов, пропущен шаг миграции) не теряются:
  откладываются в `winterarc:corrupt:<время>`, на их место кладутся чистые данные,
  на экране — сообщение.
- Данные новее приложения: экран «Нужно обновление», ничего не сохраняется,
  чтобы старая версия не затёрла новые данные.
- Импорт бэкапа идёт через тот же `migrate()` (логика готова, кнопки — этап «з»).
- Правило: изменил типы в `domain/types.ts` → подними `CURRENT_VERSION`
  и добавь шаг в `migrations.ts`. Старые шаги не трогаем никогда.
- Шкалы оценок по умолчанию (энергия, настроение, фокус) создаются вместе
  с пустыми данными.

### Арка

- По умолчанию: с 1 октября по 31 декабря начинаем сегодня и до 31 декабря;
  в остальное время года предлагаем ближайшие 1 октября – 31 декабря.
  В последние дни декабря — минимум неделя.
- Длина арки — от 7 дней до года. Название обязательно, до 60 символов.
- Отсчёт «N дней до конца» не считает сегодняшний день: 1 октября — 91,
  31 декабря — «сегодня последний день арки». До старта — «N дней до начала».
- «Пройдено %» — доля прожитых дней до сегодняшнего: 0% в первый день,
  100% после конца.
- Завершить арку — в настройках, с подтверждением. Арка уходит в историю
  со статистикой, привычки остаются; сразу открывается онбординг новой арки,
  где привычки прошлой уже выбраны. Шаблоны с теми же названиями
  второй раз не предлагаются.

### Онбординг

- Три шага: арка (название, даты, сверху — число дней и зарубки, которые
  меняются вместе с датами), «зачем» (можно пропустить), привычки.
- Шаблоны: тренировка, отбой до 23:30, учёба, чтение, вода, холодный душ.
  Любой можно поправить.
- Советуем 3–5 привычек; начать можно с одной.
- «Своя привычка» открывает полную форму всех трёх типов (она же используется
  на экране привычек). Расписание: «Ежедневно / По дням / Гибко» (N раз в неделю).
- «Зачем» показывается на главном экране под отсчётом.

### Прочее

- Тесты дат идут в часовом поясе Europe/Berlin (переход на зимнее время
  25 октября 2026), чтобы ловить ошибки «23-часовых» суток.
- Поля дат — обычным шрифтом, не моноширинным: иначе дата не влезает в половину
  строки на 360px.

## 5. Решения этапа «в»

### Чек-ин

- Открываются дни от начала арки до сегодня (стрелки ‹ ›), всё сохраняется сразу.
  До старта арки — экран «Арка начнётся …».
- Сверху — индекс дня и «N из M по плану».
- Квадрат «сделано»: у «да/нет» — отметка; у количества и времени — заполнить
  до цели одним нажатием (повторное — сбросить в 0). Точное значение — степпером:
  ±1 у количества, ±5 минут у времени, число можно ввести руками.
  У недельной цели по времени квадрата нет — только минуты.
- Привычки не по плану в этот день (например, выходные у «по будням») —
  в свёрнутом списке «Не по плану».
- Оценки 1–10: повторное нажатие на выбранную снимает оценку.

### Серии и статистика

- Серия по дням: считаются только дни по плану; сегодняшний невыполненный день
  серию не рвёт — он ещё идёт.
- «N раз в неделю» и недельная цель по времени — серия в неделях. Текущая неделя
  и первая (неполная) неделя провалом не считаются.
- Индекс недели готов в domain (у каждой привычки равный вес; у гибких привычек
  в текущей неделе цель пропорциональна прошедшим дням). Виджет — этап «г».

### Страница привычки

- Четыре плитки статистики за арку (серии — за всё время) и график.
- Графики по правилам dataviz: один ряд — без легенды, под заголовком — пояснение;
  выполненное белым, остальное серым, линия цели сплошная; круглые деления оси;
  подсказка при наведении и та же информация таблицей («Показать таблицей»).
  Количество и время за день — последние 4 недели по дням; недельные — по неделям;
  «да/нет» — % выполнения по неделям.
- Recharts грузится отдельным файлом только на этой странице.
- Тип привычки при правке не меняется: история записана в его формате.
- «Убрать в архив» — привычка пропадает из чек-ина и списка, история остаётся
  и по-прежнему учитывается в индексе прошлых дней.

### Прочее

- Prettier (`npm run format`): одинарные кавычки, строки до 100 символов.
- Отложено: порядок привычек перетаскиванием, возврат из архива, правка шкал
  оценок — в настройки (этап «з»).

## 6. Правки после этапа «в»

### Тип «Отказ» убран

По решению владельца удалены полностью: тип привычки «Отказ», «Тяга сейчас»
(таймер и дыхание), срывы и их причины, счётчик сэкономленных денег, страница
отказа и его виджеты, шаблоны отказов. Остаются три типа: да/нет, количество, время.

- Данные: версия схемы 2. Миграция v1 → v2 удаляет привычки-отказы, их записи,
  события `abstainEvents`, виджеты `moneySaved` и `settings.currency`, убирает
  отказы из списков привычек арок. Старые данные перед миграцией сохраняются
  копией в `winterarc:backup:v1`.
- Зарубки показывают только индекс дисциплины яркостью; сегодняшний день светится.
  Красных зарубок нет.
- Красный (`danger`, `danger-text`, `danger-soft`) — только для просроченных задач
  и дедлайнов. Ошибки в формах — белым текстом со значком «!» и белой рамкой поля,
  подтверждения («Завершить арку», «Убрать в архив») — белой кнопкой.

### Отступ под навигацией

- Высота нижнего бара — переменная `--wa-nav-height`. Контент снизу отступает на
  высоту бара + выступ кнопки «Чек-ин» + safe-area + запас, поэтому последние
  кнопки экрана при прокрутке до конца всегда над баром.

## 7. Решения этапа «г»

### Командный центр

- Сверху всегда арка: название, отсчёт «N дней до конца», зарубки, «День N из M»,
  «Пройдено %». Это не виджет, его нельзя убрать.
- При первом открытии за день отсчёт и индекс недели «пересчитываются» от нуля.
  Когда было последнее открытие, помнит только это устройство
  (`winterarc:last-open` в localStorage, вне данных приложения).
- Ниже — виджеты в сетке из двух колонок: узкий — половина ширины, широкий — вся.
  «Настроить» включает режим правки: у каждого виджета ↑ ↓ (переставить),
  ½ / 1 (размер), × (убрать), сверху — «Добавить» (каталог; виджеты про одну
  привычку или шкалу спрашивают, про какую).
- Виджеты: индекс недели (с разницей к прошлой), неделя (семь столбиков
  по индексу дня), сегодня (что отмечено; узкий — только «N / M»), серия привычки,
  оценка (среднее за 14 дней и линия), тепловая карта привычки за всю арку,
  «Зачем». Цель и задачи добавятся на этапе «д».
- Набор по умолчанию: индекс недели и неделя рядом, «Сегодня», «Зачем».
- Данные v3: типы `countdown` и `arcProgress` убраны; миграция v2 → v3 убирает их
  из раскладки, а пустую раскладку (до v3 настроить было нельзя) заполняет
  набором по умолчанию. Набор записан в шаге миграции целиком, чтобы шаг
  никогда не менялся.

### Индекс недели

- Сегодняшний день идёт: пока по привычке сегодня ничего не сделано, он в индекс
  недели не входит (как и в сериях). В понедельник утром — «Неделя только
  началась» вместо нуля. Прошлая неделя считается целиком.

## 8. Решения этапа «д»

Модель данных не менялась (цели и задачи были в ней с этапа «б»), миграции нет.

### Цели

- Два вида: **по шагам** (список шагов с отметками) и **числовая**. У числовой
  два режима записей: **пополнения** (каждая запись прибавляется: ₽, км) и
  **замеры** (каждая запись — новое значение: вес). Цель может идти вниз
  (вес 84 → 78), пополнения — только вверх.
- Вид цели и режим записей после создания не меняются: записи уже сделаны в их
  смысле. Название, срок, старт, цель и единица — правятся.
- Цель достигнута, когда прогресс дошёл до 100%: `completedAt` ставится сам после
  любого изменения и сам снимается, если прогресс откатился (сняли шаг, удалили
  запись, добавили шаг). Достигнутые — в свёрнутом списке «Достигнутые».
- Новая цель привязывается к текущей арке (`arcId`), срок по умолчанию — конец арки.
  Варианты срока: «Без срока», «Конец арки», своя дата.
- «Убрать в архив» прячет цель; её задачи остаются. Виджет архивной цели просит
  убрать и его.
- Шаги отмечаются, добавляются (поле внизу списка) и удаляются в режиме «Править»
  прямо на странице цели, записи числовой цели — так же.

### Темп и прогноз (числовые цели)

- Пополнения: темп = всё пополненное / дни от начала цели до сегодня.
  Замеры: темп = (последний замер − старт) / дни от начала цели до этого замера.
- Прогноз «при таком темпе — к …»: остаток / темп. Считается, только когда данных
  хотя бы за неделю (иначе одна запись даёт фантастический прогноз) — до этого
  пишем, с какого дня он появится. Темп в обратную сторону — «цель не приблизится».
- При дедлайне: «успеваешь» или «чтобы успеть, нужно +X в неделю» (меньше двух
  недель до срока — «в день»).
- Маленький график под прогрессом: верх — цель, низ — старт (для цели вниз —
  наоборот), так что линия всегда идёт к краю.

### Задачи

- Задача: что сделать, цель (необязательно), приоритет (низкий / обычный / высокий),
  срок («Нет», «Сегодня», «Завтра», дата).
- Порядок открытых задач: по сроку (просроченные сами оказываются сверху, без срока —
  в конце), при одном сроке — по приоритету, дальше — кто раньше создан.
  Сделанные — в свёрнутом списке «Сделано», последние сверху.
- В строке задачи: срок, «важно» (только у высокого приоритета), цель.
  Нажатие на строку — правка; там же удаление (с подтверждением).

### Красный

- Красным (`danger-text`, значок — `danger`) выделяется только просроченное:
  срок задачи или цели прошёл, а она не сделана. «Сегодня» — белым, остальные
  сроки — серым. В заголовке вкладки «Задачи» — «N просрочено» красным.

### Экран и виджеты

- Экран «Цели» — две вкладки: «Цели» и «Задачи». Вкладка хранится в адресе
  (`/goals?tab=tasks`), поэтому виджет задач ведёт сразу на неё.
- Страница цели `/goals/:goalId`: прогресс, шаги или записи с прогнозом,
  задачи этой цели, «Изменить», «Убрать в архив».
- Виджет «Цель» (узкий — процент и полоса, широкий — ещё срок и прогноз)
  и «Задачи» (4 ближайшие, отмечать можно прямо в виджете). В каталоге теперь все
  виджеты, реестр компонентов полный.
- Числа — по-русски (`lib/formatNumber.ts`): пробел между тысячами, запятая,
  настоящий минус «−»; вычисленные числа (темп) округляются по величине.

## 9. Решения этапа «е»

Экран «Аналитика» — четыре вкладки, вкладка хранится в адресе (`?tab=habits`).
Считается текущая арка от старта до сегодня; до старта — «Арка ещё не началась».

### Арка

- Итоги: средний индекс недель, лучшая неделя, дней с индексом 100, отметок за арку.
- Календарь по месяцам (настоящая таблица: недели × дни недели). Под каждым
  числом — черта-зарубка, яркость = индекс дня, как у ленты зарубок; сегодня
  светится. Числа в клетках не закрашиваем: белый текст на светлой клетке не
  читался бы, а тёмный текст в палитре запрещён.
- Индекс по неделям — столбики: завершённые белые, текущая серая (ещё идёт),
  будущие пустые, чтобы была видна длина арки.

### Привычки

- По каждой привычке: «цель выполнена в 34 из 40 дней по плану» (гибкие — в неделях)
  и тепловая карта всей арки. Сегодня считается, только если уже выполнено;
  первая неполная и текущая неделя — только если цель недели выполнена.

### Оценки

- По каждой шкале: среднее за арку, линия средних по неделям, серая линия — среднее
  за арку. Лучший и худший день недели — когда в каждом есть хотя бы 3 оценки.

### Связи

- «В дни с выполненной привычкой «Тренировка» энергия выше на 1,2» и «в дни, когда
  в заметке есть «устал», настроение ниже на 2,9». Под каждой — обе средние
  и сколько дней в каждой группе.
- Сравниваются только закончившиеся дни (сегодня ещё идёт). Привычка — дни, когда
  она стояла в плане (у гибких — любой день, «сделано» = что-то отмечено).
  Слова — только дни с заметкой: дни без заметки ничего не говорят о словах.
- Показываем разницу от 0,5 балла, если в каждой группе хотя бы 4 дня;
  самые сильные — сверху, до 8 в списке. На экране прямо написано: связь, а не причина.
- Слова: строчными, без служебных («после», «очень», «сегодня»…), короче трёх букв
  не берём; «ё» = «е» при сравнении, но показываем как написано. Слова с одинаковыми
  первыми пятью буквами — одно слово («тренировка», «тренировки»). Слова, которые
  встречаются ровно в одни и те же дни, объединяются в одну связь
  («прогулка», «друзьями» и «отличное»).

### Графики

- По правилам dataviz: один ряд — без легенды, пояснение под заголовком; столбики
  до 24px со скруглённым верхом, линия 2px с точками 8px; сетка тонкая сплошная;
  подсказка при наведении и «Показать таблицей». Recharts — отдельными файлами (lazy).

### Отложено на этап «з»

- Основной файл сборки перерос 500 КБ — разнести экраны по отдельным файлам (lazy).

## 10. Решения этапа «ж»

Модель данных не менялась (`weeklyReviews` и `achievements` были в ней с этапа «б»).

### Обзор недели

- Экран `/review`, неделя — в адресе (`?week=2026-11-02`), стрелки ‹ › от первой
  недели арки до текущей. В понедельник по умолчанию открывается прошлая неделя
  (итоги подводят за закончившуюся), в остальные дни — текущая.
- Итоги считаются сами: индекс недели и разница с прошлой; по каждой привычке
  «5 из 7 дней» (дневные), «2 из 3 раз» («N раз в неделю», в том числе время
  с таким расписанием), «90 из 150 мин» (недельная цель по времени); лучший
  и худший день (только закончившиеся, при равенстве — более ранний); средние
  оценки и «раньше» (прошлая неделя); сколько задач сделано, шагов к целям,
  целей достигнуто.
- Три вопроса: что получилось, что не получилось, фокус на следующую неделю.
  Сохраняются кнопкой «Сохранить» → «Сохранено». Все поля пустые — обзор удаляется.
- Фокус из прошлого обзора показывается сверху следующей недели.
- В воскресенье (за эту неделю) и в понедельник (за прошлую), пока обзора нет,
  в командном центре под аркой — «Подведи итоги недели».

### Ледяные жетоны

- Серии по каждой привычке: 7 / 30 / 60 / 90 дней подряд, у гибких — 2 / 4 / 8 / 12
  недель (лучшая серия за всё время). Рубежи: время — 10 / 50 / 100 часов,
  количество — 100 / 1000 единиц. Дисциплина: первая отметка, идеальный день
  (индекс 100), 10 идеальных дней, идеальная неделя. Цели: первая и 5 целей,
  10 и 50 задач. Обзоры: 1, 4, 12. Арка: экватор (половина дней) и арка до конца.
- Жетон считается из фактов, а получение записывается в данные с моментом
  получения (`{ id: "streak-30:<habitId>", unlockedAt }`). Полученный жетон остаётся
  навсегда, даже если потом удалить отметку.
- Проверка — `useAchievementUnlocks` в оболочке: через 0,4 с после изменения данных
  (чтобы не считать на каждую букву заметки). Новые жетоны — сообщение над нижней
  навигацией на 6 секунд, с переходом к «Достижениям». При первом запуске
